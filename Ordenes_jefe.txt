ASUNTO: Mandato de Desarrollo Crítico - Proyecto "StreamlitPRO v2 AI"

MISIÓN:
Tu única prioridad es realizar una reingeniería completa del software de web scraping ubicado en el directorio /v2. El producto final será una aplicación Streamlit que replique al 100% la funcionalidad y estética de la versión original, pero reemplazando su obsoleto motor de scraping con una arquitectura de IA superior, optimizada para una velocidad y fiabilidad absolutas.

CONTEXTO Y MATERIAL DE REFERENCIA:
El directorio /v2 contiene una aplicación Flask funcional. Analízala a fondo. Es el modelo a seguir en términos de resultado final para el usuario. Ignora por completo su metodología de scraping interna (Selenium/Playwright/requests); será reemplazada en su totalidad.

REQUERIMIENTOS NO NEGOCIABLES:

1. MOTOR DE SCRAPING (La Nueva Arquitectura):

Tecnología Mandatoria: Implementarás la extracción de datos utilizando exclusivamente la siguiente pila tecnológica:

Orquestador de Rastreo: Crawl4AI para gestionar la navegación y la identificación de contenido.

Proveedor de IA: Groq para la ejecución del modelo de lenguaje.

Cerebro de Extracción: DeepSeek como el LLM para interpretar el HTML y estructurar los datos.

Prohibición Absoluta: No se utilizará Selenium, Playwright o requests para la extracción principal de datos de la página de resultados. Su uso queda obsoleto y reemplazado.

2. FRAMEWORK DE LA APLICACIÓN:

Plataforma: La aplicación final debe ser construida al 100% en Streamlit. Deberás portar toda la lógica de la interfaz de usuario y la interacción del app.py de Flask a un paradigma de Streamlit.

Paridad Funcional: La aplicación Streamlit debe ofrecer exactamente las mismas funcionalidades que la versión de Flask en /v2: visualización de partidos, filtrado por hándicap y cualquier otra característica presente. Sin excepciones.

3. INTERFAZ Y EXPERIENCIA DE USUARIO (UX/UI):

Paridad Visual: La estética debe ser idéntica. Analiza los archivos HTML y CSS dentro de /v2/templates y replica el estilo, colores, fuentes, espaciado y diseño de manera impecable en la interfaz de Streamlit. El usuario final no debe notar la diferencia en el frontend.

Carga de Datos Instantánea: La presentación de datos debe ser percibida como instantánea. Implementa operaciones asíncronas (async/await) para todo el proceso de scraping y utiliza los mecanismos de caché de Streamlit (st.cache_data, st.cache_resource) de manera inteligente para garantizar que los datos se muestren al usuario a la máxima velocidad posible tras la extracción inicial.

4. FIABILIDAD Y RENDIMIENTO:

Cero Fallos: El sistema debe ser robusto. Implementa un manejo de errores exhaustivo. Si el sitio web objetivo no responde o la API de Groq falla, la aplicación Streamlit debe mostrar un mensaje de error claro y profesional al usuario, sin crashear.

Optimización de Costos y Velocidad: La lógica debe estar diseñada para minimizar el número de tokens enviados al LLM. Utiliza el CSS_SELECTOR de manera precisa para aislar únicamente los nodos HTML que contienen la información de los partidos antes de enviarlos a DeepSeek.

ESTRUCTURA DEL PROYECTO ESPERADA:

Organizarás el código de manera modular y profesional:

StreamlitPRO/

.env (Para la clave de API de GROQ)

streamlit_app.py (El punto de entrada principal de la aplicación Streamlit)

ai_scraper.py (Módulo que contiene toda la lógica de Crawl4AI y DeepSeek)

models.py (Módulo para las definiciones de esquemas Pydantic, ej: MatchResult)

config.py (Para constantes como la URL y el CSS_SELECTOR)

requirements.txt (Listado de todas las dependencias)

ENTREGABLE:
Un directorio de proyecto limpio que contenga el software funcional, siguiendo la estructura definida. El software debe ejecutarse sin errores tras instalar las dependencias de requirements.txt y configurar el archivo .env.

PLAZO: Inmediato.

Ejecuta con precisión. No se aceptarán desviaciones de estas directrices. El éxito se mide por una réplica funcional y visualmente idéntica que opere con una velocidad y eficiencia superiores.
